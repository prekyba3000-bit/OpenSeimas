# Evaluation SECA-05 — independent summary approval and admin audit

2026-11-25. Branch `fix/eval-stage1`, code commit `aa6a7b3`.

## What changed

- **Drafting and approval have different credentials.** General admin routes use
  `SYNC_SECRET`; summary drafting also accepts `SUMMARY_DRAFT_SECRET`; approval
  accepts only `SUMMARY_APPROVE_SECRET`. The three secrets must be distinct, and
  missing or shared credential configuration fails closed with 503.
- Negative route tests prove the general and draft tokens cannot approve, the
  approval token cannot draft, and the draft token cannot use general admin
  routes.
- **The server names the approver.** `approved_by` is removed from the approval
  schema and written from `SUMMARY_APPROVER_NAME`. A caller-supplied
  `approved_by` is ignored; the public response carries the configured name.
- **The batch publisher no longer approves.** `scripts/publish_summaries.py`
  requires the draft-only secret and makes one request per summary, to create a
  draft. Its final output says that separate approval is required.
- **Migration 057 adds `admin_audit_log`.** Rows record timestamp, static route,
  credential identity and entity, never request bodies or secret values.
  Corrections, methodology, summaries, approvals and replies write their audit
  row in the same transaction; refresh and sync triggers are audited before
  background work is queued. Triggers reject UPDATE, DELETE and TRUNCATE.
- Render, local-env examples and operator handoffs document the credentials.
  The approval secret is stored separately from the batch publisher's
  environment.

No LLM rephrasing caller exists in the current Python source. If one is added,
a wording gate or explicit reviewer-diff control is still required; source-bound
figures and a separate approval credential do not by themselves constrain added
evaluative wording.
