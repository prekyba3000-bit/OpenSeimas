## What changed

- **`backend/publish.py`** is the one publish step: run the gate; on HOLD refresh
  nothing; otherwise refresh `mp_stats_summary`, `mp_leaderboard_metrics`,
  `mp_attendance_v2`, `faction_alignment` (CONCURRENTLY; a view created WITH NO
  DATA gets one plain first fill) and record each in `source_fetches` with the
  caller as `job_id`. Gate exit 2 (no `dq_checks` table) still refreshes, as the
  script did.
- `dq_check_runner.main()` accepts a DSN from the caller.
- The in-memory `_refresh_state` and the unauthenticated
  `GET /api/admin/refresh-status` that reported it are gone. No consumer in the
  repo; `/api/meta/freshness` reports publication from `source_fetches`.

## Part 2 — the profile reads the published row

- `hero_engine._fetch_mp_metrics` no longer recomputes the vote, speech and
  committee rollups live from `mp_votes`, `speeches` and `committee_memberships`.
  It reads them from `mp_leaderboard_metrics`, whose definition computes the same
  rollups with the same predicate (checked against the live view definition).
  The separate live `speeches` count in `calculate_hero_profile` is gone.
  Attendance still comes from `mp_stats_summary` (NULL-preserving), not the
  leaderboard view, which coalesces it to 0.
- **A member with no published row** (added since the last publish, or during a
  HOLD) gets `null` for every figure and dimension and provenance
  `"unpublished"`, kept distinct from `"unavailable"` (§1.2). Before, the same
  member got live numbers, and the empty-database golden profile carried 0.0 for
  every figure.
- Wire contract: `HeroDimensionsResponse` fields Optional; zod `dimensions.*`
  nullable; the 12 paths declared in `contracts/wire-nullability.json`;
  `heroes-degraded.json` regenerated (0.0 → null). `readMpDimension` already
  renders null as unknown. Old client + new backend breaks only for an
  unpublished member, and production has none.
- Production before deploy (read-only): 0 members without a published row; live
  and published speeches, committee roles and bills agree for every member. So
  no displayed figure changes at deploy, and no methodology entry is needed (the
  computation is the same; only when it publishes changed).

## Part 3 — a failing check holds what it protects

The gate was all-or-nothing: stale registrations (attendance only) also held
vote counts and faction alignment, and a `legislation` duplicate — a table no
published view reads — held everything.

- **Publication units** (`backend/publish.py`): `members` = mp_stats_summary +
  mp_leaderboard_metrics (the list reads one, the profile the other, so they
  must move together); `attendance` = mp_attendance_v2; `faction` =
  faction_alignment_votes + faction_alignment. A unit publishes or holds whole.
  `publish()` returns `published`, `partial` or `held`, with the checks holding
  each held unit.
- **Migration 060**: `dq_checks.protects` (NULL = every unit, the default for a
  check nobody scoped; `{}` = none; `{by_source}` = map each failing row's
  `source_name` through the new `dq_source_units`, where an unmapped source holds
  every unit). A check that could not run holds every unit regardless.
  Scopes were derived, not guessed: each check's inspected tables against each
  view's source tables (`pg_depend` on production).

| Check | Holds |
|---|---|
| politicians / mp_votes / votes checks (6) | all three units |
| sitting_day_without_registrations | attendance |
| legislation_project_id_unique_not_null | nothing (recorded only) |
| frozen_feed, metric_backing_source_stale, three_way_reconciliation | by source |

  Sources: votes → all; registrations → attendance; floor speeches, authored
  bills → members; sessions, decrees, diary, travel, assistants → none.
- `dq_check_runner.held_units()` reports the held units; per-source checks keep
  every failing source, not just the 5-row sample. Runner and data-health
  tolerate a database without 060. `/api/internal/data-health` now lists each
  check's `protects`, and `publish_held` ignores a failing check that protects
  nothing (per-source checks still count as holding: the safe direction).

Tests (real Postgres): eight scope cases — scoped check, mapped source
(attendance / members / none), unmapped source, empty scope, no scope, a check
that cannot run — each asserting exactly which views refreshed and were
recorded; every enabled blocking check declares a scope; every unit named in
`dq_source_units` exists; every published view belongs to a unit. Backend
**564 passed**.

Production: 060 applied (`1 applied, 59 already up-to-date`); dry run 14 checks,
0 blocking; publish refreshed all five views.

Known limit: within the `members` unit, stale speeches or authored bills still
hold vote counts, because one view computes all of them. Splitting the unit
means splitting the view.
